Where does our emissions choice matter most?

How much warmer each place gets than it was in 1995–2014, under a low- and a high-emissions future. climate models, 20-year averages. How we made this

The vertical axis stays fixed, so places can be compared. Click the chart to change the period.

About this graphic

What we found

  • The choice shows up late, but it is made early. Averaged over the globe, the two futures differ by only 0.09°C in 2021–2040. The gap grows to 0.64°C in 2041–2060 and 2.83°C in 2081–2100 (+1.2°C versus +4.1°C). The emissions paths split in 2015, so the late-century gap comes from decisions made decades earlier.
  • The far north carries the most. North of the Arctic Circle the 2081–2100 gap is 2.2 times the global gap. Over land it is 1.6 times the gap over the ocean.
  • Land sees it first. By 2041–2060 the gap is clear over 48% of the land but only 3% of the ocean. For the world as a whole it becomes clear in 2046–2065.
  • Some places stay uncertain. South of Greenland, 3 of the 18 models get less warming on the high path, and the gap never becomes clear there by 2100. About 1% of the globe is like this.
  • San Diego's gap (+2.9°C) is almost exactly the global average.

Design decisions

Visual encodings

  • Equal Earth projection. It keeps areas true, so the amount of dark red is honest. Mercator or a plain latitude–longitude grid would stretch the high latitudes, which is exactly where our biggest values are.
  • One colour scale for all three temperature views. Low, high and gap share the same eight classes, so a colour always means the same number of degrees and switching views compares like with like. Within ±0.5°C is a neutral grey for “about no change”, and blue is kept for cooling. We binned the colours rather than using a continuous ramp so values can be read off the legend, and so the class boundaries visibly move when the animation plays.
  • A separate scale for “When it shows”. This view encodes time, not temperature, so it uses its own single-hue blue scale (darker means sooner) that cannot be mistaken for degrees.
  • Smooth map, honest values. The 2.5° grid is drawn pixel by pixel with bilinear interpolation. Tooltips use the same interpolation, so the number under the cursor always matches the colour.
  • The line chart. High emissions is always orange and low emissions always blue. Each shaded band covers the middle 80% of models. The vertical axis is fixed, so a place with an 8°C gap looks bigger than one with 3°C. A vertical line marks when the place's gap becomes clear.

Interaction

  • Four views switch what the map measures: each future, the gap between them, and when the gap becomes clear.
  • The slider and Play button move through 20-year periods. Animation is what shows the timing: the gap map stays almost grey until mid-century, then fills in from the north.
  • Hover for exact values and the model range. Click to pin a place and chart it. The place buttons give a quick tour, including San Diego. Clicking the chart moves the map to that period, so the two views stay linked.
  • Notes on the map are recalculated for every view and period. Each one hides itself when its claim stops being true, so the notes are never stale.

Alternatives we considered

  • Three maps side by side. At web widths each would be too small to show 2.5° detail, so we used one large map with a toggle.
  • A blue–red scale centred on zero. Almost every value is warming, so half of the colours would go unused.
  • One frame per year. Every frame is already a 20-year average, so yearly frames would add five times the data with no visible difference.
  • A line for every model. Eighteen overlapping lines per future were unreadable, so we kept the band.

Data and transformations

  1. Source. Monthly near-surface air temperature (tas) from the CMIP6 archive on Google Cloud, for the historical runs and the SSP1-2.6 and SSP5-8.5 scenarios.
  2. Models. One model per institution, so no modelling centre counts twice, and one run per model that exists in all three experiments. That gives 18 models: .
  3. Annual means, weighting each month by its length.
  4. A common grid. Every model is interpolated to 2.5° (144 by 72 cells). We checked each model's global average on this grid against its native grid; they agree to within 0.012°C.
  5. Warming. Each model is compared with its own 1995–2014 average, which removes differences in each model's starting climate.
  6. 20-year averages, every 5 years. The period labelled 2081–2100 averages exactly those years, so 2021–2040, 2041–2060 and 2081–2100 match the periods the IPCC uses.
  7. Ensemble. The map shows the plain average of the models. Bands and tooltip ranges are the 10th to 90th percentile across models.
  8. The gap is high minus low, worked out inside each model before averaging, so its range reflects disagreement about the gap itself.
  9. “Clear” means the 10th percentile of the gap is above 0.5°C (so 9 in 10 models agree it is at least that big) and stays above it in every later period. We chose 0.5°C because it is the step between the 1.5°C and 2°C Paris targets.

Caveats. These are raw model averages. The set includes some high-sensitivity models, so it runs warmer than the IPCC's assessed ranges, which also draw on other evidence. The bands show how far the models spread, not a probability. The code that prepares the data is in project3/pipeline.

What took the most time. Preparing the data took the longest. Downloading the 54 model runs was quick, but checking them was not. Three runs stored their 20-year files out of time order and had to be sorted. Comparing every model's global average before and after regridding showed that one model (FGOALS-g3) uses unevenly spaced latitudes, which a simple area weighting gets wrong. Next came the map renderer: drawing the grid pixel by pixel through the projection, and fixing a bug where D3 wraps longitudes, which painted colour outside the globe. Testing the finished page turned up smaller problems, such as a legend that collapsed and a tooltip that went stale while the animation played.

Tools and sources

All plotting uses D3 v7.9.0. topojson-client only decodes the outlines, which come from Natural Earth through world-atlas. The data was prepared in Python with xarray, zarr and gcsfs.
